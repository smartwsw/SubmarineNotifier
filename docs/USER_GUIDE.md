# USER GUIDE — 安装与使用

> 面向**普通玩家**：只需要安装插件、填一个服务器地址、配置 Bark。不需要 Node.js，不需要自己跑服务。

---

## 1. 开始之前

你需要：

- 已安装 **XIVLauncher** 与 **Dalamud**；
- 一个已经部署好的通知服务地址（形如 `https://submarine-notifier.xxx.workers.dev`）。
  如果你没有自己的服务，向提供服务的人索取地址；
- 一部 iPhone（Bark）或安装了 ntfy 的手机。

> 服务器地址不是「账号密码」。注册时插件会自动向该服务申请一个只属于你的用户 ID 与 token。

---

## 2. 安装插件

### 2.0 如果你拿到了插件仓库地址（推荐）

1. 游戏内 `/xlsettings` → **实验性 / Experimental** → **自定义插件仓库 / Custom Plugin Repositories**。
2. 在输入框粘贴仓库地址（以 `pluginmaster.json` 结尾），点 `+` 添加，再点保存。
3. `/xlplugins` → 切到「全部 / All」，搜索 **Submarine Return Notifier**，点安装。
4. 之后插件有新版本时，`/xlplugins` 里会出现更新提示。

没有仓库地址就走下面的手动安装。

### 2.1 解压到开发插件目录

1. 拿到 `SubmarineReturnNotifier` 的发布包（`latest.zip`）。
2. 打开目录 `%APPDATA%\XIVLauncher\devPlugins\`（在资源管理器地址栏粘贴即可）。
3. 新建文件夹 `SubmarineReturnNotifier`，把 zip **里的文件**解压进去（不要多一层目录）。

解压后应能看到：

```
%APPDATA%\XIVLauncher\devPlugins\SubmarineReturnNotifier\
  SubmarineReturnNotifier.dll
  SubmarineReturnNotifier.Core.dll
  SubmarineReturnNotifier.deps.json
  SubmarineReturnNotifier.pdb
  SubmarineReturnNotifier.json
```

### 2.2 启用插件

1. 启动游戏（或重启游戏）。
2. 输入 `/xlplugins`，切到「开发插件 / Dev Plugins」标签页。
3. 找到 **Submarine Return Notifier**，勾选启用。

启用后聊天框会提示「插件已加载」或「等待登录」。

### 2.3 卸载

- 在 `/xlplugins` 中取消勾选，或
- 关闭游戏后删除 `%APPDATA%\XIVLauncher\devPlugins\SubmarineReturnNotifier\` 整个目录。

插件配置保存在 `%APPDATA%\XIVLauncher\pluginConfigs\SubmarineReturnNotifier.json`，卸载插件后可以一并删除。

---

## 3. 绑定服务

1. 游戏内输入 `/subnotify`，打开设置窗口。
2. 切到 **绑定** 页。
3. 在输入框填入服务地址，例如 `https://submarine-notifier.xxx.workers.dev`。
4. 「设备名称」可以随意填（多台电脑时用于区分）。
5. 点 **保存地址**，再点 **注册新设备**。

成功后会显示：

- 用户 ID（`usr_...`）
- 设备 ID（`dev_...`）
- Token 前缀（`srk_xxxx…`）

> **关于 Token**：完整 token 只在注册成功那一刻下发，插件已自动保存在本地配置里。云端只保存它的哈希，**任何人也包括服务提供者都拿不回完整值**。如果丢失，只能重新注册。

点「连接测试」应显示「连接正常」。

### 已经有账号了？用「加入已有账号」

「注册新设备」会创建一个**全新的独立账号**。如果你已经在别的电脑上绑定过，请不要重复注册，
而是在第二台电脑上：

1. 在**已绑定**的那台电脑打开 `/subnotify` → **绑定** 页；
2. 点 **复制 Token**（完整 token 只保存在本机配置里，云端无法找回）；
3. 到新电脑的 **绑定** 页，把 Token 粘贴到「已有设备的 Token」输入框；
4. 填好设备名称，点 **加入已有账号**。

成功后两台电脑的用户 ID 相同：潜水艇记录、推送设置、通知历史都是同一份。
旧电脑不受影响，想撤销新设备可以用 API `DELETE /auth/devices/:id`（见 [API.md](API.md)）。

> Token 等同于账号权限，只粘贴到自己的设备上，不要发给别人。

## 4. 配置 Bark

1. 在 iPhone 上安装 [Bark](https://apps.apple.com/app/bark-customed-notifications/id1403753865)。
2. 打开 Bark，复制首页的 **Device Key**（形如 `AbCdEfGhIjKlMn`）。
3. 回到游戏的插件窗口，切到 **推送** 页。
4. 确认「启用返航通知」已勾选。
5. 「推送方式」选择 **Bark**。
6. *Bark Server URL* 填 `https://api.day.app`（除非服务提供者给了你自建地址）。
7. *Bark Device Key* 粘贴刚复制的 Key。
8. *通知分组* 可留空或填 `FF14`。
9. **务必检查「时区」**，中国玩家应填 `Asia/Shanghai`（默认是 UTC，不改会导致通知时间差 8 小时）。
10. 点 **保存并测试**，手机应立即收到一条测试通知。

保存后 Device Key 输入框会被清空，这是正常的：云端加密保存，界面不再回显。需要更换时直接粘贴新 Key 再保存；留空保存表示「保持原值」。

### 使用 ntfy

推送方式选 **ntfy**，填入 Server URL（默认 `https://ntfy.sh`）与一个自己起的 Topic 名。
如果用的是公开服务器，建议再填一个 Access Token，否则任何知道 Topic 的人都能订阅你的通知。

## 5. 确认能读到潜水艇

1. 进入你的 FC 房屋，打开 **工坊 → 潜水艇** 面板一次（点开就行，不需要出航）。
2. 回到 `/subnotify` → **状态** 页，点 **手动刷新**。
3. 表格里应列出每个槽位的潜水艇：名称、状态（航行中 / 已返航 / 停泊）、返航时间、剩余时间。

如果表格为空且提示「工坊数据未加载」，说明游戏客户端还没拿到工坊数据 —— 再进一次工坊面板即可。

> **换了电脑时**：游戏只在客户端加载过工坊数据后才提供潜艇信息。新电脑刚登录、还没打开工坊时，
> 插件读不到数据，会显示「展示的是本机缓存」并提示打开面板。此时云端仍保留另一台电脑上报的较新记录，
> 通知照常触发，不会因为这台电脑"看不到"就把已排定的通知取消。

> 插件不是任何时候都能读到潜水艇数据，它依赖游戏客户端已经加载过工坊信息。一次成功读取后，返航时间就已经上传到云端，之后即使关游戏也会正常通知。

## 6. 通知会是什么样

### 正式返航通知

标题：`潜水艇返航`

正文：

```
2 艘潜水艇已返航
· 潜水艇A — 11/12 18:30
· 潜水艇B — 11/12 18:30
```

### 提前通知（如果开启）

标题：`潜水艇返航（即将返航）`

正文：

```
2 艘潜水艇将于 11/12 18:30 前后返航
· 潜水艇A — 11/12 18:30
· 潜水艇B — 11/12 18:30
```

### 合并规则

返航时间相差不超过「合并窗口」（默认 10 分钟）的潜水艇会合成**一条**通知，避免一次收到好几条。
例如 20:00、20:05 两艘同时返航 → 只发一条，在 20:05 发送；20:25 那艘单独发一条。

可以在「推送」页调整：

- **合并窗口**：0–120 分钟（0 = 每条单独推送）
- **提前通知**：关闭 / 提前 1 / 5 / 10 / 15 / 30 分钟
- **通知标题、正文模板、时区**

正文模板支持占位符：`{count}`（数量）、`{kind}`（已返航 / 即将返航）、`{submarines}`（潜水艇列表）。

设置页底部有**实时预览**，显示的就是云端将会发出的内容。

### 想立刻验证推送效果？

推送页底部有 **立即发送下次返航**。它让云端把「下一次真实会发出的通知」马上推一遍，
所以收到的就是正式通知的原文（包括标题、时区、合并结果），而不是一条写死的测试文案。

- 它**不会改动发送计划**：到点了正式通知仍会照常再发一次，不会因为预览而漏发。
- 需要云端已有待发批次（即插件至少成功上报过一次数据）。
- 提示「云端没有待发的返航通知」时，回到工坊面板让插件重新上报即可。
- 每次都会写一条 `next` 类型的发送记录，不会污染返航通知的去重记录。

## 7. 日常使用

| 场景 | 你需要做什么 |
|---|---|
| 每天正常玩 | 什么都不用做。进过工坊后插件会自动同步。 |
| 派潜艇出航 | 出航后进一次工坊面板（或等插件自动检查），让新的返航时间上传。 |
| 关机出门 | 不用管，云端已排好通知。 |
| 换电脑 | 旧电脑「绑定」页点 **复制 Token**，新电脑装好插件后在「加入已有账号」里粘贴该 Token 并点按钮。之后两台电脑共用同一份数据与推送设置；**新电脑要打开一次工坊→潜水艇面板**才能读到本机数据。 |
| 不小心点了「注册新设备」 | 那会创建一个新账号。用上一条的「加入已有账号」重新并入原账号即可（旧账号的数据不会自动迁移到新账号）。 |
| 换角色 | 自动跟随当前登录角色，数据在云端按角色分开存。 |
| 不想再收到通知 | 「推送」页取消勾选「启用返航通知」并保存。 |

### 命令

| 命令 | 作用 |
|---|---|
| `/subnotify` | 打开设置窗口 |
| `/subnotify scan` | 立即重新扫描一次工坊数据 |
| `/subnotify sync`（或 `upload`） | 立即强制上传当前状态到云端 |

## 8. 状态页怎么看

- **当前角色**：显示角色名与 ContentId；「工坊数据未加载」时展示的是上次缓存。
- **上次成功上传**：最近一次云端确认接收的时间。
- **有待上传的变化 / 最近一次失败**：失败时会显示原因和下次自动重试时间。
- **云端连接**：最近一次检查云端的状态。
- **云端待处理批次**：点「检查云端」后显示，表示云端还有几条待发通知。

---

## 9. 诊断页

- **本地缓存**：显示缓存文件路径，出问题时可以把文件发给服务提供者协助排查。
- **输出调试日志**：勾选后 Dalamud 日志里会有更多细节（日志已自动脱敏，不会包含 token / Bark Key）。
- **自动检查间隔**：默认 60 秒。游戏内内容没变时不会发请求，调小不会增加云端负担，只是本地读取得更勤。
- **最近错误**：最近 20 条本地错误记录，可清空或重置缓存。

---

## 10. 删除账号

「绑定」页最下方有 **删除云端账号**（需点两次确认）。

这会永久删除你在云端的**全部**数据：潜水艇记录、推送配置、通知历史，并取消所有待发通知。本地插件配置里的 token 也会被清除。

此操作不可撤销。

---

## 11. 收不到通知怎么办

按顺序检查：

1. **Bark App 本身能不能收到？** 在 Bark 里点自带的测试通知。
2. **「保存并测试」有没有收到？** 没收到说明 Device Key 或服务地址有问题，见 [TROUBLESHOOTING.md](TROUBLESHOOTING.md)。
   测试推送能收到、但「立即发送下次返航」提示「云端没有待发的返航通知」，则说明数据没上报成功 —— 回工坊面板刷新一次。
3. **状态页有没有潜水艇？** 没有说明工坊数据没读到。
4. **云端待处理批次是多少？** 点「检查云端」，为 0 且潜水艇返航时间在未来，说明还没到点。
5. **时区对不对？** 时区错误只会让显示时间错，不会导致收不到通知。
6. **手机通知权限**是否允许 Bark 发送通知、系统是否开了专注模式。

更多细节见 [TROUBLESHOOTING.md](TROUBLESHOOTING.md)。
